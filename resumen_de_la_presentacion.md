🎯 Contexto y Objetivo PrincipalEl Reto: Participación en el "Reto UI Generativa Banorte x Tec de Monterrey".  Misión de la IA: El modelo (LLM) no debe limitarse a contestar con bloques de texto; debe interpretar la intención financiera del usuario, decidir qué componentes mostrar y construir una interfaz gráfica (UI) dinámica en tiempo real que resuelva el problema.  Dominio: Servicios y productos financieros (Banca personal, inversiones, crédito, pagos, seguros, o educación financiera). El equipo elige el problema específico.  Experiencia Cíclica: La pantalla se arma según la intención. Lo que el usuario toca o interactúa en esa UI debe regresar al modelo como contexto para disparar nuevas acciones o rediseñar la experiencia.  ⚙️ Base Técnica Común (No Negociable)El sistema debe estar compuesto obligatoriamente por estas tres piezas:  LLM (El centro): Interpreta, decide y orquesta la experiencia.  MCP (Model Context Protocol): Expone al modelo los datos, las herramientas y las acciones construidas por el equipo.  A2UI (Agent-to-UI o equivalente): Protocolo utilizado para representar y transmitir la interfaz generada por el agente para que sea renderizada.  Arquitectura de flujo: Usuario expresa necesidad ➔ Agente/LLM interpreta ➔ MCP provee datos/herramientas ➔ A2UI describe la UI ➔ Se renderizan Componentes accionables ➔ La interacción regresa al Agente.  📜 Reglas de Construcción para el EquipoComponentes propios: El equipo debe diseñar y programar su propio sistema de componentes de UI (simuladores, tablas, formularios, etc.); no se entrega una biblioteca prehecha.  Datos y APIs propios: Los datos deben ser creados o integrados por los participantes (pueden ser sintéticos, simulados o de fuentes públicas).  Al menos un flujo accionable: Es obligatorio que la UI generada permita a la persona interactuar y que esa interacción produzca un cambio o acción real.  Libertad de Stack: Se permite usar cualquier lenguaje, framework, modelo o proveedor de infraestructura adicional.  📦 Entregables RequeridosDemo: Una corrida en vivo del flujo completo (intención ➔ UI generada ➔ interacción ➔ acción).  Código: Repositorio que incluya los componentes, el servidor MCP y la capa A2UI, con instrucciones para correrlo.  Datos: Las APIs y datasets (servicios creados), incluso si son sintéticos.  Documentación Técnica: Diagrama de arquitectura y justificación de decisiones (trade-offs sobre modelo, protocolo e infraestructura).  ⚖️ Criterios de Evaluación45% Producto y UI: Cumplimiento y utilidad para el usuario (25%) + Calidad y adaptabilidad de la UI generada (20%).  30% Ingeniería: Calidad de la solución de IA (15%) + Arquitectura e ingeniería (15%).  25% Diseño y Presentación: UX y diseño (10%) + Innovación (10%) + Presentación (5%).
